# Hive Sync Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task.

**Goal:** Build the approved single-hub hive with durable offline replicas, per-computer file ownership, pairing, and recoverable conflicts.
**Architecture:** Browser-safe reconciliation is shared by the SQLite agent/hub and IndexedDB browser replica. Operations carry immutable base/next snapshots initially; the reconciler derives semantic field and placement changes. This trades bandwidth for a small, auditable protocol while preserving stable operation IDs and causal context.
**Tech Stack:** TypeScript, React/Zustand, Fastify, Node 22 SQLite, IndexedDB, service worker.
**Spec:** docs/superpowers/specs/2026-09-20-hive-sync-design.md

## Global Constraints

Preserve Outline File and Bullet IDs. One owner per file. Never interpret another device's path locally. All members may edit every branch offline. Preserve conflicting candidates. Hub acceptance and owner disk persistence are separate acknowledgments. No deployment or migration of real user files during development. Worktree: /tmp/lister-hive-sync, branch feat/hive-sync.

## Shared contract

`@lister/core/hive` is browser-safe. `SharedFile` has id, name, ownerId, optional parentId, and bullets. `HiveSnapshot` has rootFileId, files keyed by file ID, and conflicts. `HiveOperation` has id, replicaId, base, next, optional resolves (conflict IDs). `applyHiveOperation(current, operation)` returns reconciled snapshot. `emptyHive()` returns an empty snapshot. Conflict records expose id, bulletId, field, base, current, proposed, operationId.

HTTP local endpoints: GET /api/hive/status; POST /api/hive/create {name,label}; POST /api/hive/join {invitation,label}; POST /api/hive/invite {address}; GET /api/hive/snapshot; POST /api/hive/operations {operations}; POST /api/hive/sync; POST /api/hive/register {filePath}; POST /api/hive/revoke {deviceId}. Snapshot response: {snapshot,cursor,generation,hiveId,deviceId}. Status includes enabled, role, label, hiveId, connected, pending, error, fileStatus. Transport /api/hive/peer/* is authenticated. Browser uses an authenticated local session when hive enabled; pairing/setup is available from loopback, with an explicit session token for remote use.

## Verification and rulings

Implemented on `feat/hive-sync` in `/tmp/lister-hive-sync`. Full build/tests and isolated Chrome smoke cover offline reload, browser restart, conflicting edits, resolution, stable-ID undo/redo and offline import. Independent review findings received regression tests and fixes for rejected identity dependencies, ambiguous sibling moves, stale transfer-source edits, bounded upload batches, failed setup watcher preservation, and history rollback/divergence.

History discontinuities intentionally block sync while preserving local state and export; automatic restoration across divergent histories is not attempted. Snapshot envelopes favor correctness and inspection over bandwidth. An unresolved parent identity blocks dependent placements until explicit review. Some structural file recovery requires exported candidates and manual relinking rather than overwriting an existing registered file. No live user installation was migrated.
